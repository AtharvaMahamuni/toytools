# IndexNow

Automated [IndexNow](https://www.indexnow.org/) submission for ToyTools. On every production
deploy, the public URL list is derived from the Content Manifest and POSTed to the IndexNow
aggregator, which notifies participating search engines (Bing, Yandex, Naver, Seznam, …) of
new and updated pages.

## 1. What IndexNow is

IndexNow is an open protocol that lets a site **push** a list of changed URLs to search engines
instead of waiting for them to crawl. You verify ownership by hosting a key file at the site
root (`https://<host>/<key>.txt` whose body equals the key), then POST a JSON payload listing
your URLs. One POST to `api.indexnow.org` fans out to every participating engine.

## 2. Why ToyTools uses it

It shortens the time between publishing/updating a tool, guide, or category and the change
being picked up. It is **complementary** — it does not replace any existing SEO surface:

- `robots.txt` and `sitemap-index.xml` still drive Google + general crawling.
- Google Search Console / Bing Webmaster Tools are unaffected.

IndexNow simply adds a fast notification channel for the engines that support it.

## 3. Architecture overview

Everything derives from the existing **Content Manifest** (`src/lib/content/manifest.ts`) —
the same single source of truth the sitemaps use. There is **no parallel URL registry** and
**no manual tool enumeration**.

```
src/config/indexnow.ts        ── env-driven config (key, host, enabled, endpoint)
public/<key>.txt              ── ownership key file (auto-copied to dist/)
src/lib/indexnow/
  collectUrls.ts              ── manifest → absolute → normalize → de-dupe  → string[]
  normalizeUrl.ts             ── https-only, canonical host, no query/fragment, trailing slash
  buildPayload.ts             ── string[] → { host, key, keyLocation, urlList } (+ validation)
  client.ts                   ── POST to IndexNow; retry once; never throws → SubmitResult
src/pages/indexnow-urls.json.ts ── build-time dist/indexnow-urls.json audit artifact
scripts/submit-indexnow.ts    ── `npm run indexnow` CLI (always exits 0)
```

`scripts/platform-health.ts` validates IndexNow coverage and the key file as part of the
post-build integrity superset (WARN-only — it never blocks a deploy).

## 4. URL collection flow

1. `buildContentManifest()` yields every indexable surface: home, categories, tools, guides,
   language stubs. It already **excludes** redirect stubs, the legacy `/faq/` redirects,
   `/search`, `/architecture`, `/404`, `robots.txt`, and all `*.xml` meta routes.
2. `collectUrls(site)` maps each entry's site-relative URL to absolute (`new URL(url, site)`),
   runs it through `normalizeUrl`, and de-dupes — preserving manifest order (deterministic).
3. `normalizeUrl` forces `https:`, rejects any non-canonical host, strips the query string
   (including `utm_*`) and fragment, and enforces a single trailing-slash form so `/x` and
   `/x/` never both appear (ToyTools uses `trailingSlash: 'always'`).

## 5. Build integration

`astro build` automatically emits two files into `dist/`:

- `dist/<key>.txt` — copied verbatim from `public/<key>.txt`.
- `dist/indexnow-urls.json` — `{ generatedAt, count, urls }`, generated by the
  `src/pages/indexnow-urls.json.ts` endpoint.

No extra build step is required. `npm run health` then warns if coverage drifts or the key
file is missing / mismatched.

## 6. GitHub Actions integration

`.github/workflows/deploy.yml` runs three jobs: `build` → `deploy` → `indexnow`. The
`indexnow` job runs **after** a successful deploy, in isolation:

```yaml
indexnow:
  needs: deploy
  continue-on-error: true   # IndexNow can never fail the pipeline
  steps:
    - checkout / setup-node 22 / npm ci
    - npm run build          # regenerates dist/indexnow-urls.json (artifact isn't shared here)
    - npm run indexnow       # submits; always exits 0
```

Deployment success is independent of IndexNow by two mechanisms: `continue-on-error: true` on
the job, and `process.exit(0)` on every path of the CLI.

## 7. Troubleshooting

| Symptom | Check |
|---|---|
| `disabled (INDEXNOW_ENABLED=false)` | Unset `INDEXNOW_ENABLED` or set it to anything but `false`. |
| `URL list is empty` | `collectUrls()` returned nothing — verify the registry/manifest builds. |
| Non-200/202 status | IndexNow rejects on key-file mismatch — confirm `dist/<key>.txt` body equals the key. |
| Key file 404 in production | Ensure `public/<key>.txt` exists and matches `INDEXNOW_KEY`; rebuild. |
| `off-host` / `non-https` warnings in `npm run health` | A manifest URL is malformed; fix the source entry. |

## 8. Verification steps

```sh
# 1. Build, then confirm the artifacts exist
npm run build
cat dist/81433a8e29464f45ab05cb1242e6483a.txt   # → the key, no trailing newline
cat dist/indexnow-urls.json                      # → { generatedAt, count, urls }

# 2. Coverage + key-file integrity (WARN-only)
npm run health

# 3. Unit tests (normalize/collect/payload/client)
npm run test

# 4. Graceful no-op when disabled
INDEXNOW_ENABLED=false npm run indexnow

# 5. Real submission (idempotent; resubmitting is safe)
npm run indexnow

# 6. After deploy — the published key file must return the key
curl https://toytoolsapp.com/81433a8e29464f45ab05cb1242e6483a.txt
```

## Incremental optimization (future)

`collectUrls()` is a pure function so a future `collectChangedUrls(prev, curr)` can diff two
URL sets and submit only what changed. This requires persisting the previous build's URL list
(e.g. as a CI artifact). It is intentionally **not** implemented today — the extension point is
the purity of `collectUrls()` and the `dist/indexnow-urls.json` snapshot.
